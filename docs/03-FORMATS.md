# 03 — الصيغ والترميز (Formats & Codecs)

> هذا الملف هو **المرجع الوحيد** لاختيار الصيغ. لا تخترع صيغة افتراضية خارج هذه الأشجار.

## مبادئ
1. **الكفاءة أولًا** متى أمكن (AVIF > HEIC > WebP > JPEG/PNG في نسبة الجودة/الحجم).
2. **لا تُتلف الشفافية:** أي صورة فيها قناة ألفا (PNG غالبًا) لا تُحوّل أبدًا إلى JPEG.
3. **تجنّب البراءات في الـ binary:** HEVC/HEIC/H.264 تُستخدم عبر مُشفّر النظام فقط — المنصّة هي مَن يتكفّل بترخيص البراءات. لا تُحمّل `libx264`/`libx265` داخل الـ binary مهما كانت الإغراءات.
4. **اكشف القدرة** قبل اختيار صيغة تتطلّب عتادًا (HEIC/AVIF).

## ملخص الرخص + البراءات

المشروع نفسه مرخَّص بـ **GPL-3.0**. هذا يُنهي مسألة "هل أستطيع تضمين مكوّن GPL؟" — نعم تستطيع، لأن الناتج النهائي copyleft على أي حال. لكن GPL لا يحمي من **براءات الاختراع** التي تثقل بعض الـ codecs، ولذلك نختار صيغنا بعناية:

| الصيغة/الكوديك | الإتاوات/البراءات | الترخيص العملي | القرار |
|---|---|---|---|
| **AVIF / AV1** | royalty-free (AOMedia) | libavif/aom = BSD | ✅ مفضّل (عبر `flutter_avif`) |
| **WebP / VP9** | royalty-free (Google) | BSD | ✅ آمن دائمًا |
| **JPEG / PNG** | منتهية/حرّة | حرّ | ✅ توافقية |
| **HEIC / HEVC** | براءات (patent pools) | استخدم **مُشفّر النظام فقط** | ⚠️ مسموح عبر OS، ممنوع تجميعه في الـ binary |
| **H.264** | براءات (مرخّص واسعًا) | عبر مُشفّر النظام | ⚠️ عبر OS فقط |
| **x264/x265 (libx26x)** | GPL + براءات نشطة | — | ❌ لا تُضمّن في الـ binary |

النتيجة: للفيديو نعتمد **المُشفّر الأصلي للنظام** (المنصّة تتكفّل بالبراءات)، ولـ FFmpeg variant **LGPL** بلا x264/x265 — هذا ليس لأن GPL مشكلة لنا (المشروع GPL أصلاً)، بل لأن x264/x265 يحملان عبء براءات يُعقّد التوزيع في بعض الولايات القضائية.

## شجرة قرار صيغة الصورة (ضغط/تحويل)

```
هل للصورة شفافية (alpha)؟
├─ نعم → الصيغ التي تحفظ الألفا فقط:
│        AVIF(alpha) → HEIC(alpha) → WebP(alpha) → PNG (احتياطي)
│        ❌ لا JPEG أبدًا
└─ لا  → مسار الكفاءة:
         هل الجهاز يشفّر AVIF بكفاءة (وكُشف ذلك)؟ والمستخدم اختاره/سمح بالبطء؟
         ├─ نعم → AVIF
         └─ لا  → هل يشفّر HEIC بالعتاد؟
                  ├─ نعم → HEIC
                  └─ لا  → WebP (افتراضي آمن) ← أو JPEG لأقصى توافقية
```

ملاحظات:
- **الافتراضي «تلقائي»** يطبّق هذه الشجرة. المستخدم المتقدّم يستطيع فرض صيغة معيّنة.
- AVIF بطيء الترميز → لا يكون افتراضيًا على الأجهزة الضعيفة؛ يُعرض كخيار «أعلى كفاءة (أبطأ)».
- عند تحويل صيغة، **حافظ على الميتاداتا** افتراضيًا (إلا في ميزة حذف الميتاداتا) عبر نقل EXIF/الـ ICC profile.
- انتبه: تحويل صورة بعمق لوني/HDR (10-bit) إلى صيغة 8-bit يفقد المدى — أبقِ العمق إن أمكن (AVIF/HEIC يدعمان >8-bit).

## شجرة قرار الصورة المتحركة

المصدر: فيديو (ببداية/نهاية أو كامل) أو مجموعة صور. التحكّم: fps/السرعة + الأبعاد.

| الصيغة | المميزات | متى نقترحها |
|---|---|---|
| **AVIF متحرك** | أعلى كفاءة (حجم صغير جدًا + جودة عالية + ألفا) | خيار «أعلى كفاءة» — عبر `flutter_avif`، أبطأ |
| **WebP متحرك** | متوازن، حجم أصغر بكثير من GIF، يدعم ألفا | **الافتراضي المقترح** — عبر libwebp |
| **GIF** | توافقية قصوى | عند الحاجة للمشاركة في أماكن لا تدعم WebP/AVIF |

**قاعدة جودة GIF الإلزامية:** لا تولّد GIF بمسار واحد. استخدم لوحة ألوان مخصّصة (تقلّل الـ banding):
```
# الخطوة 1: توليد اللوحة
ffmpeg -i in.mp4 -vf "fps=15,scale=480:-1:flags=lanczos,palettegen" palette.png
# الخطوة 2: استخدام اللوحة
ffmpeg -i in.mp4 -i palette.png -lavfi "fps=15,scale=480:-1:flags=lanczos[x];[x][1:v]paletteuse" out.gif
```
للـ WebP المتحرك: استخدم libwebp مع `-loop 0` وجودة قابلة للضبط؛ وللـ AVIF المتحرك استخدم `flutter_avif`.

من صور إلى متحرك: رتّب الإطارات + `-framerate` للتحكّم بالسرعة، ثم الصيغة المطلوبة.

## شجرة قرار الفيديو

### حذف الصوت (نظيف 100%)
```
ffmpeg -i in.mp4 -c copy -an out.mp4      # نسخ الفيديو بت-ببت + إزالة الصوت
```
لا إعادة ترميز إطلاقًا → لا تشويه، وسريع جدًا.

### قص (Trim)
- **عند حدود keyframe**: lossless، `-c copy`.
- **بدقّة الإطار**: smart cut (إعادة ترميز أطراف الـ GOP فقط). التفاصيل في `F3-video-editing.md`.

### قص الحواف (Crop) / تغيير الأبعاد
- يتطلّب **إعادة ترميز حقيقي** (لا توجد طريقة lossless لقص منطقة عشوائية).
- استخدم المُشفّر الأصلي بهدف جودة (quality VBR/CRF-equivalent) قريب من المصدر، مرّة واحدة فقط.
- لا تستخدم حيلة «الكتابة فوق الفيديو» (display matrix / crop metadata) لأنها تنكسر عند المشاركة/النقل.

### ضغط/تغيير صيغة
- الحاوية: mp4 (افتراضي توافقي) / mkv / webm.
- الكوديك عبر المُشفّر الأصلي: H.264 (توافقية) أو HEVC/AV1 (كفاءة، إن توفّر عتادًا).
- تحكّم المستخدم المتقدّم: هدف الجودة، الدقة، الـ fps، الحاوية.

### قاعدة التشويه الذهبية للفيديو
- **لا تعيد ترميز إلا لمرّة واحدة وللضرورة.**
- النسخ (`-c copy`) دائمًا مفضّل حين تسمح العملية.
- إذا اضطُررت لإعادة ترميز الصوت: AAC ≥ 256k أو احتفظ بالكوديك الأصلي بالنسخ.

## مصفوفة «ماذا يلمس ماذا»

| العملية | إعادة ترميز فيديو؟ | إعادة ترميز صوت؟ | الأداة |
|---|---|---|---|
| حذف الصوت | لا | لا | FFmpeg `-c copy -an` |
| قص عند keyframe | لا | لا | FFmpeg `-c copy` |
| قص دقيق (smart cut) | الأطراف فقط | الأطراف فقط | FFmpeg + native |
| قص حواف / تحجيم | نعم (مرّة) | لا (نسخ) | Native encoder |
| ضغط فيديو | نعم (مرّة) | حسب الحاجة | Native encoder |
| فصل الموسيقى | لا (نسخ) | نعم (مرّة، AAC≥256k) | ONNX + FFmpeg دمج |
| ضغط/تحويل صورة | — | — | flutter_avif / image_compress / system |
