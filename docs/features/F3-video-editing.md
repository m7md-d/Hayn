# F3 — تحرير الفيديو (Video Editing)

> القاعدة الذهبية: **لا تعيد ترميز إلا للضرورة، ومرّة واحدة.** المرجع: `03-FORMATS.md`.

## 1) القص (Trim)

### أ) قص lossless عند keyframes
- ممكن فقط حين تقع نقاط القص على **keyframes (I-frames)**.
- `ffmpeg -ss <kf> -i in.mp4 -t <dur> -c copy out.mp4` → نسخ بت-ببت، بلا تشويه، سريع.
- عيبه: نقاط القص «تقفز» لأقرب keyframe، فالدقّة ليست بالإطار.

### ب) القص الدقيق بالإطار (Smart Cut)
المشكلة: المستخدم يبي يقص عند إطار محدّد، لكن `-c copy` لا يستطيع القص داخل GOP، وإعادة ترميز الفيديو كامل = تشويه وحجم.

الحل (smart cut):
1. أعد ترميز **مقطع البداية الجزئي** فقط (من الإطار المطلوب حتى أول keyframe تالٍ).
2. **انسخ المنتصف** كما هو (`-c copy`) بين الـ keyframes.
3. أعد ترميز **مقطع النهاية الجزئي** فقط.
4. ادمج الثلاثة (concat) بنفس كوديك/معاملات المصدر لتفادي قطع مرئي.

النتيجة: دقّة بالإطار + إعادة ترميز للأطراف فقط (تشويه ضئيل جدًا ومحلّي) بدل الفيديو كامل. أعد الترميز بالمُشفّر الأصلي (native) بمعاملات قريبة من المصدر.

## 2) قص الحواف (Crop) / تغيير الأبعاد
- **يتطلّب إعادة ترميز حقيقي** — لا توجد طريقة lossless لقص منطقة بكسلات.
- **لا تستخدم حيلة الـ crop/display-matrix metadata**: المستخدم يشكو منها بحق — تنكسر عند المشاركة أو الفتح في تطبيق/منصّة أخرى (يظهر الفيديو الأصلي كاملًا أو ينكسر التوجيه).
- الحل النظيف: إعادة ترميز **مرّة واحدة** بالمُشفّر الأصلي بهدف جودة قريب من المصدر (quality-based VBR/CRF-equivalent)، فيبقى الحجم معقولًا والجودة عالية، والناتج يعمل في كل مكان.
- طابق كوديك/profile/مستوى المصدر قدر الإمكان لتقليل التغيّر.

## 3) الضغط والتحكّم بالصيغة
- المُشفّر الأصلي (MediaCodec/VideoToolbox) عبر platform channel في `native/`.
- تحكّم المستخدم المتقدّم: هدف الجودة، الدقة، الـ fps، الكوديك (H.264 توافقي / HEVC / AV1 إن توفّر عتادًا)، الحاوية (mp4/mkv/webm).
- التلقائي يختار هدفًا متوازنًا حسب `DeviceCapabilities`.

## 4) حذف الصوت (نظيف 100%)
```
ffmpeg -i in.mp4 -c copy -an out.mp4
```
لا إعادة ترميز إطلاقًا. (مرتبط بـ F5 عند إعادة دمج صوت مُعالَج.)

## مزامنة وحالات حرجة
- **VFR (معدّل إطارات متغيّر):** عالجه بعناية لتفادي انزياح الصوت/الصورة؛ اضبط timestamps عند إعادة الترميز.
- HDR: حافظ على معلومات اللون (transfer/primaries) عند إعادة الترميز.
- كل عملية = task مع تقدّم/إلغاء؛ الطويلة تحت foreground service (Android).
